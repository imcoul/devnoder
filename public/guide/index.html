DevNoder guide

Edit useful browser projects, see a supported preview, and keep a recoverable local copy.

What runs here

DevNoder is a static web application. Project files are edited in the browser. The clearest supported loop is HTML, CSS, and classic JavaScript: create or import a project, open its first file, edit it, preview the result, and export a ZIP backup.

Preview is not a general package manager or native build environment. Arbitrary npm modules, framework compilers, native SDKs, and device-specific toolchains are not implied by a file being editable.

Projects and formats

  • Browser files such as .html, .css, .js, .json, and other editor-supported text files can be stored and edited.
  • Visual editing and other panels may support narrower formats; their status should be treated as capability-specific rather than universal.
  • Static preview is intended for browser-runnable content. Imports that require a server, native binary, package install, or private backend need that environment outside this app.

Storage and recovery

Project data is kept in browser-local storage for this app. Clearing site data, changing browser profiles, or storage pressure can remove access to local work. Export a ZIP backup before clearing data or moving devices, and keep important backups somewhere outside the browser. DevNoder does not promise automatic recovery of cleared local storage.

GitHub

The Git panel can save a repository origin and use a GitHub personal access token for the supported remote operations. Token material is kept in the existing encrypted browser-local storage path; it is not stored as a plain devnoder-gh-token value. Network access, repository permissions, and GitHub availability still apply. Disconnect removes the stored token.

AI setup

AI setup is in one AI workspace. DevNoder exposes supported local WebLLM and Transformers.js/ONNX paths where the selected model and browser runtime are compatible, along with configured provider routes when available. Model downloads can require network access, storage, memory, and time; provider calls can require a key, network access, quota, and the provider's own policy.

Model quality and device compatibility vary. DevNoder does not claim that arbitrary GGUF files, every model, or native inference can run in this browser.

Development

Clone the repository from GitHub, install the pinned Node dependencies, and use npm run dev for local work. The supported checks include npm run typecheck, npm test, and the project’s Playwright flows when their environment is available. Production publishing is controlled by the live deployment branch; do not treat a local build as a deployment.

If you are unsure whether a workflow is supported, look for an explicit capability state in the app and keep an exportable backup. “Editable” does not mean “runs here.”
